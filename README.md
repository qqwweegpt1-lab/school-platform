# منصة الانضباط والمواظبة السلوكية

موقع مدرسي عربي (RTL) بإشراف **أ. منال الجهني — وكيلة الشؤون الطلابية**، يتيح للطالبات وأولياء الأمور تقديم إشعارات الغياب والتأخر وطلبات الاستئذان، وإرسال المقترحات والشكاوى والآراء، ومتابعة حالة الطلبات، والاطلاع على الإعلانات والمبادرات ونتائج الاستبانات. ولوحة إدارة محمية لإدارة كل ذلك.

## ما تم تنفيذه فعليًا (واختُبر)

| المجال | الحالة |
|---|---|
| الصفحة الرئيسية، الشعاران، العنوان، النص التعريفي، قائمة تنقل بقائمة فرعية، قائمة جوال | منفّذ |
| صوت الطالبة، آراء أولياء الأمور، المقترحات، الشكاوى | منفّذ (محفوظة في قاعدة البيانات) |
| إشعار الغياب / إشعار التأخر / طلب الاستئذان (نماذج مستقلة + مرفقات PDF/JPG/PNG) | منفّذ |
| رقم مرجعي فريد + رمز متابعة سري + صفحة متابعة الحالة | منفّذ |
| وسائل التحفيز، نتائج الاستبانات، إعلانات المدرسة، تغطية الفعاليات (صور/فيديو) | منفّذ ومُدار من اللوحة |
| لوحة الإدارة (بحث وتصفية، تغيير الحالة، ملاحظات داخلية، سجل الحالات، المستخدمون) | منفّذ |
| صلاحيتان: مشرفة (admin) وموظف مخوّل (staff — لا يرى الشكاوى ولا مشاركات الطالبات ولا آراء أولياء الأمور) | منفّذ ومُتحقَّق منه على الخادم |
| بيانات تجريبية موسومة + حذفها بضغطة | منفّذ |

الاختبارات: 47 اختبارًا آليًا (`npm test`) واختبار واجهة بمتصفح حقيقي على الحاسوب والتابلت والجوال (`npm run test:ui`)، وكلها ناجحة.

## التقنيات، وما يختلف عن المطلوب

- **Node.js 22.18+ مع TypeScript** (تشغيل مباشر بإزالة الأنواع، دون خطوة بناء)، و**SQLite المدمجة في Node** (`node:sqlite`)، **بلا أي اعتماديات تشغيل**.
- **لم يُستخدم Next.js ولا Tailwind ولا PostgreSQL.** السبب: بيئة التطوير التي بُني فيها المشروع لا تستطيع الوصول إلى سجل npm، فلم يكن ممكنًا تثبيت تلك الحزم أو تشغيلها أو اختبارها. اخترنا بديلًا يمكن تشغيله واختباره فعليًا. نظام الألوان موحّد بمتغيرات CSS في أول ملف `public/css/app.css`.
- الخطوط: Tajawal من Google Fonts (يعود الموقع لخط النظام إن تعذّر تحميله). الأيقونات SVG مضمّنة.
- إن أردتم لاحقًا الانتقال إلى Next.js/PostgreSQL فالمخطط (`db/migrations/001_init.sql`) ومنطق التحقق (`src/forms.ts`, `src/services.ts`) قابلان لإعادة الاستخدام.

## التشغيل محليًا

```bash
cd school-platform
cp .env.example .env          # ثم عدّلوه (انظروا أدناه)
npm run create-admin          # إنشاء حساب المشرفة الأول (تفاعليًا)
npm run seed                  # (اختياري، للتطوير) بيانات تجريبية موسومة
npm start                     # http://127.0.0.1:3000
npm test                      # الاختبارات الآلية
npm run typecheck             # فحص الأنواع (يتطلب: npm i)
```

لا يوجد حساب مدير افتراضي ولا كلمة مرور في الكود. تُنشأ قاعدة البيانات وتُطبَّق الترحيلات تلقائيًا عند أول تشغيل.

### إنشاء حساب المدير الأول بأمان
- تفاعليًا: `npm run create-admin` (تُدخل كلمة المرور دون إظهارها).
- أو عبر متغيرات بيئة مؤقتة: `ADMIN_USERNAME=... ADMIN_DISPLAY_NAME="أ. منال الجهني" ADMIN_PASSWORD=... npm run create-admin` ثم امسحوها من سجل الطرفية.
- كلمة المرور: 10 أحرف على الأقل وتحتوي أحرفًا وأرقامًا، وتُخزَّن مشفّرة (scrypt). من اللوحة يمكن إضافة موظفين وإعادة تعيين كلمات المرور.

### المتغيرات (`.env.example`)
`PORT`, `HOST`, `NODE_ENV`, `DATA_DIR`, `APP_SECRET`, `COOKIE_SECURE`, `TRUST_PROXY`, `MAX_ATTACHMENT_MB`, `MAX_ATTACHMENTS`, `SUBMIT_LIMIT_PER_HOUR`. في الإنتاج **يجب** ضبط `APP_SECRET` (32 حرفًا فأكثر؛ يرفض الخادم الإقلاع دونه).

## قاعدة البيانات والمرفقات
- الملف: `storage/platform.db` (SQLite، وضع WAL). الترحيلات في `db/migrations/` وتُطبَّق تلقائيًا بالترتيب. لإضافة تعديل مستقبلي أنشئوا `002_...sql`.
- الجداول: المستخدمون والجلسات، الطلبات (الغياب/التأخر/الاستئذان/المقترحات/الشكاوى/مشاركات الطالبات/آراء أولياء الأمور في جدول واحد بحقل نوع)، سجل الحالات، الملاحظات الداخلية، المرفقات، الإعلانات، المبادرات، الاستبانات وعناصرها، الوسائط، الإعدادات، سجل التدقيق.
- المرفقات تُحفظ في `storage/attachments/` والوسائط في `storage/media/` — خارج `public/`، بأسماء عشوائية، ولا تُقدَّم إلا عبر مسارات تتحقق من الصلاحية. يُتحقق على الخادم من النوع الفعلي (من محتوى الملف) والحجم (الافتراضي 5 ميغابايت للمرفق، و3 مرفقات).
- **انسخوا مجلد `storage/` احتياطيًا بانتظام** (يشمل القاعدة والمرفقات).

## الأمان والخصوصية (ما نُفِّذ)
جلسات بملفات تعريف ارتباط HttpOnly وSameSite، تخزين تجزئة رمز الجلسة فقط، قفل مؤقت بعد محاولات دخول فاشلة وتحديد معدل، حماية CSRF لكل نماذج POST والتحقق من Origin، استعلامات SQL مرتبطة المعاملات فقط، تهريب كل مخرجات HTML (حماية XSS) مع ترويسات CSP وغيرها، التحقق من الصلاحيات في كل مسار على الخادم، فخ الروبوتات ومنع تكرار الإرسال (nonce)، رمز متابعة سري مجزّأ يُعرض مرة واحدة، لا تظهر الشكاوى ولا بيانات الطالبات ولا المرفقات في أي واجهة عامة، ومشاركات الطالبات لا تُنشر إلا بعد مراجعة وبلا أسماء، والوسائط لا تُنشر دون تأكيد الموافقة.

## ما يجب إعداده قبل الإنتاج (لم يُنفَّذ لأنه خدمات خارجية)
1. **الإشعارات**: المنصة **لا ترسل** رسائل نصية ولا بريدًا؛ يتابع أولياء الأمور الحالة من صفحة المتابعة. للإرسال الفعلي يلزم ربط مزوّد SMS/بريد.
2. **HTTPS**: انشروا خلف وكيل عكسي (nginx/Caddy) وفعّلوا `COOKIE_SECURE=true` و`TRUST_PROXY=true`.
3. **سياسة الخصوصية** (`/privacy`) مسودة إرشادية: يجب أن تراجعها المدرسة وتعتمدها. لا ندّعي توافقًا نظاميًا كاملًا دون مراجعة الجهة المختصة.
4. **النسخ الاحتياطي** لمجلد `storage/` ومدة الاحتفاظ بالبيانات.
5. تحديد حدّ المعدل حاليًا في ذاكرة العملية (يكفي لخادم واحد).
6. فحص الفيروسات للمرفقات غير مُفعَّل (يُتحقق من النوع والحجم فقط).

## النشر (خادم Linux مثال)
```bash
NODE_ENV=production APP_SECRET=... COOKIE_SECURE=true TRUST_PROXY=true HOST=127.0.0.1 PORT=3000 node src/server.ts
```
شغّلوه بخدمة systemd أو pm2 خلف nginx/Caddy يعيد التوجيه إلى المنفذ 3000، وحدّدوا `client_max_body_size 70m` إن رفعتم فيديو. الفحص الصحي: `/healthz`.

## ما الذي أعدّله؟
| أريد تغيير | الملف |
|---|---|
| اسم المنصة، المشرفة، اسم المدرسة، الصفوف، تصنيفات الإعلانات والوسائط | `src/config.ts` |
| النص التعريفي وعنوان الترحيب | من اللوحة: «محتوى الصفحة الرئيسية» |
| الألوان والخطوط | متغيرات `:root` في `public/css/app.css` |
| **شعار المدرسة** | استبدلوا `public/img/school-logo.jpg` |
| **شعار وزارة التعليم** | استبدلوا `public/img/moe-logo.png` |
| حقول النماذج وقواعد التحقق | `src/forms.ts` |
| نص سياسة الخصوصية | دالة `privacyPage` في `src/pages/public.ts` |

الصفوف في `src/config.ts` مضبوطة على **المرحلة الابتدائية** (بحسب شعار المدرسة المرفق)؛ عدّلوها إن لزم.

## إضافة المحتوى (من لوحة `/admin`)
- **الإعلانات**: مسودة ← نشر / إخفاء / تثبيت / حذف، مع تصنيف وموعد فعالية وصورة اختيارية من مكتبة الوسائط.
- **وسائل التحفيز**: اسم، وصف، أيقونة، فئة مستهدفة، فترة، حالة (مسودة/نشطة/منتهية).
- **الاستبانات**: أنشئوا استبانة وأضيفوا نتائجها **المجمّعة** (سؤال/خيار/عدد أصوات) ثم انشروها. لا تُنشر نتائج افتراضية.
- **الفعاليات**: ارفعوا صورًا (JPG/PNG/WEBP) أو فيديو (MP4/WEBM) وأكّدوا الموافقة على النشر ثم انشروها.
- **البيانات التجريبية**: `npm run seed` تضيف محتوى موسومًا «بيانات تجريبية»؛ تُحذف بـ `npm run seed:clear` أو بزر في لوحة المتابعة.

## بنية المشروع
```
src/server.ts        الخادم والتوجيه وحماية CSRF
src/pages/public.ts  الصفحات العامة       src/admin/*  لوحة الإدارة
src/forms.ts         تعريف النماذج والتحقق  src/services.ts منطق الطلبات والمتابعة
src/security.ts      كلمات المرور/الجلسات/CSRF/تحديد المعدل
src/uploads.ts       التحقق من الملفات وتخزينها
db/migrations/       مخطط القاعدة          tests/  الاختبارات
```

## عن الموقع المرجعي
فُحص ملف HTML المرجعي بالكامل. اعتمدنا منه فكرة الصفحات المنفصلة بتبويبات، وبطاقات الخدمات، وبنية استبيانات الطالبات/أولياء الأمور ونتائجها. ولاحظنا أن وظائفه **وهمية**: تُخزَّن البيانات في ذاكرة الصفحة وتضيع عند إعادة التحميل، والنتائج المعروضة أرقام ثابتة مفبركة، ولا توجد مصادقة أو قاعدة بيانات. لذلك أُعيد تنفيذ تلك الأفكار بوظائف حقيقية، ولم تُنسخ منه بيانات ولا أسماء. ولم نستخدم Tailwind/Chart.js عبر CDN؛ الرسوم البيانية SVG مضمّنة.
